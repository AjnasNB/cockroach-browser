Browser automation use cases

Use Cockroach Browser when the work needs real browser state.

Pages that render, change, remember, download, upload, open tabs, or require reviewable browser evidence.

Cockroach Browser is designed for stateful browser execution. These use cases map real operational needs to the exact shipped surfaces that handle them.

Install the BrowserBrowser or Crawler?
01 / Browser workflow

AI-agent web workflows

Need: An agent must inspect a live application, identify a semantic target, interact with it, and return a reviewable result.

How Cockroach Browser handles it: Create a session, capture a semantic snapshot, act through MCP or the SDK, and retain the receipt and evidence artifacts.

MCP, BrowserRuntime, BrowserClient, snapshot, click, fill, select, capture.paired
02 / Browser workflow

Authenticated portal work

Need: A user-authorized workflow needs cookies, storage, permissions, tabs, downloads, or a visible login handoff.

How Cockroach Browser handles it: Use an isolated or runtime-owned persistent profile, headed mode when required, explicit state checkpoints, and controlled files.

persistentProfile, profile import/export, state.*, tab.*, upload, download
03 / Browser workflow

Forms and operational tasks

Need: A workflow needs real clicks, typing, selection, dialogs, file upload, downloads, or multi-step navigation.

How Cockroach Browser handles it: Target semantic refs, CSS, or XPath; run individual actions or an ordered batch; capture an outcome after each state change.

fill, type, press, select, check, dialog, upload, download, /actions/batch
04 / Browser workflow

QA and release review

Need: A team needs reproducible screenshots, PDFs, visual diffs, console and asset checks, or performance observations.

How Cockroach Browser handles it: Run the same page through capture, audits, network inspection, trace, HAR, video, and visual comparison surfaces.

screenshot, pdf, trace.*, audit.*, compare, recordHar, recordVideo
05 / Browser workflow

Local browser tool for coding agents

Need: A coding agent needs browser capability without uploading the user's browser profile to a hosted browser service.

How Cockroach Browser handles it: Run the authenticated loopback daemon, connect through MCP or the typed client, and keep profiles and evidence on the operator's machine.

serve, mcp, BrowserClient, dashboard, doctor, service install
06 / Browser workflow

Operator-managed browser workers

Need: A service needs to route sessions across several authenticated browser daemons while retaining local ownership of each worker.

How Cockroach Browser handles it: Use BrowserWorkerPool capacity and tags, worker health checks, activity streams, metrics, and team session roles.

BrowserWorkerPool, /v1/health, /v1/activity, /v1/metrics, TeamSessionStore

Use a browser when state is part of the answer.

Cookies, storage, profiles, tabs, dynamic rendering, form state, files, dialogs, downloads, page revisions, network observations, and visual artifacts all belong to a browser session. That is the center of Cockroach Browser.
